# 実装ノート

この文書は、特定の入力や個別の文書に依存しない実装上の判断をまとめたものです。
入力の内容、ファイル名、件数、変換結果の個別評価は記録しません。

## 構成

処理は次の層に分かれています。

1. コンテナをTLVとして読み、ページと付属データの範囲を確定する。
2. ページの保存形式を判定し、JPEGはそのまま、符号化ページは展開して描画モデルへ変換する。
3. PDFまたは自己完結HTMLへ、ページ内の要素を描画順に並べて出力する。

解析では、宣言された長さを上限として使い、範囲外のオフセット、過大なサイズ、循環する参照を拒否します。
未解釈の要素は、既知の構造を壊さない範囲で記録し、回収可能な要素の処理を継続します。

## コンテナ

### TLV

コンテナのフィールドは、タグと長さを持つ入れ子構造です。長さの短形式と長形式を分けて読み、
各ノードの終端を親ノードの範囲内で検証します。整数は保存形式のリトルエンディアンとして解釈します。

ページ表を追跡できない場合は、既知のページ要素の先頭を走査してページを再構成します。
このフォールバックは、ページ本体のサイズとデータ範囲が検証できる場合に限って採用します。

### ページの保存形式

ページは、JPEG、プレビュー、符号化されたメタファイル、付属データ、またはメタデータのないデータとして扱います。
ページの役割と表示属性は別々に保持し、本文ページと画像ページを混同しないようにします。

JPEGは再エンコードせず、入力のストリームをPDFまたはHTMLへ移します。画像ページが連続した帯に分割されている場合は、
画素幅などの検証済みの属性が一致する範囲だけを連結します。

## LZH展開

符号化ページに含まれる圧縮データは、ブロックごとのハフマン表を読み取って展開します。
表の要素数、符号長、ブロック長、出力上限をそれぞれ検証し、宣言された展開長と実際の出力長を一致させます。
ビット列はストリームの仕様に合わせて最上位ビットから消費します。

## メタファイル

展開後のページは、EMFまたはWMFとして読み、共通のGDIキャンバスへ変換します。
キャンバスは次の状態を持ちます。

- 論理座標からデバイス座標への変換
- フォント、ペン、ブラシ、クリップの状態
- パスの構築状態
- 画像、塗り、図形、文字の描画順

`SETWINDOWORG`、`SETVIEWPORTORG`、両方のエクステントを追跡し、すべての要素を同じデバイス座標系へ揃えます。
用紙全体を覆うクリップ矩形は無制限クリップとして扱い、狭い矩形だけを描画モデルへ保存します。

### GDI要素

対応する基本要素は、文字、折れ線、多角形、矩形、楕円、ブラシ塗り、画像配置、埋め込みDIBです。
未対応のラスタオペレーションは、内容を推測して描かず、未処理要素として扱います。
単色マスクはパレットとビット極性を正規化してから、PDFのソフトマスクまたはHTMLのアルファへ変換します。

### privateコメント

メーカー固有のコメントは、画像の定義・画像の選択・画像の配置・クリップ矩形・パス操作として解釈します。
画像の選択は出現順の識別子で管理し、同じ画像の複数配置を許します。

パス操作は、おおむね次の対応です。

| コメント | 意味 |
| --- | --- |
| `DWa` | メタファイル内の画像定義 |
| `DWb` | 次に配置する保存画像の選択 |
| `DWc` | 選択中の画像の配置 |
| `DW01` | クリップ確定 |
| `DW02` | パス開始 |
| `DW03` | パスをクリップへ反映 |
| `DW04` | パスをブラシで塗る |
| `DW05` | パスをペンで描く |
| `DW06` | クリップ矩形の設定 |

パスの命令は、現在の図形を継続するものと新しい図形を開始するものを区別します。
閉じた図形の塗りは、キャンバスの塗りつぶし規則をそのままPDFとHTMLへ渡します。

### 点列の符号化

点列のヘッダーは、命令、座標符号化、点数、始点の順です。

| 符号化 | 内容 |
| --- | --- |
| `0x20` | すべての点を符号付き16bit絶対座標で読む |
| `0x40` | 始点の後を符号付き8bit差分で読む |
| `0x80` | 始点の後を符号付き4bit差分で読む |

`0x80`では、1バイトの上位・下位ニブルをそれぞれx・yの差分として読みます。
差分値`-8`は後続の符号付き8bit値へ逃がします。レコード長から必要と判断できる場合は、
その値を後続の符号付き16bit値へ拡張する形式も受け付けます。短い入力や消費位置が宣言長と一致しない入力は拒否します。

### 描画順

z方向の順序は、メタファイルに現れる要素の順序を基本とします。文字の向きや縦書き判定を、画像と文字の前後関係を決める条件にはしません。
複数のラスタ操作が同じ配置・同じ画像に対して連続している場合だけ、操作列を一つの透過画像としてまとめます。
それ以外は、塗り、画像、図形、文字を記録された順に出力します。

## PDFとHTML

PDFではJPEGを`DCTDecode`、DIBを`FlateDecode`または対応する画像形式として埋め込みます。
パスはPDFパス演算へ変換し、クリップと塗りを`q` / `Q`の範囲で管理します。
文字は検索・コピー可能なテキストとして配置し、必要に応じて指定されたTrueTypeフォントをサブセット化します。

HTMLでは画像をdata URLとして埋め込み、座標とクリップをCSSおよびSVGで表現します。
PDFとHTMLで描画モデルを共有し、出力形式ごとの差は最後の描画処理に閉じ込めます。

## 検証方針

変更後は、少なくとも次を確認します。

1. `cargo fmt -- --check`
2. `cargo test --all-targets`
3. `cargo clippy --all-targets -- -D warnings`
4. PDFを画像へラスタライズし、ページ数、用紙サイズ、クリップ、文字、画像の前後関係を目視確認する。

比較用の入力や生成物の固有情報は、ソースコードやドキュメントへ持ち込みません。
